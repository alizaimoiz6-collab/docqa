The problem

Teams that work from long documents, such as insurance policies, claims manuals and contracts, spend a long time finding one clause. Generic AI chat gives fluent answers nobody can check, and in regulated work an answer without a source can't be used.

The solution

A service that returns a structured answer with page-level citations and verifies every quote against the document on the server. A fabricated citation is flagged before it reaches the user. When the document doesn't contain the answer, it says so instead of guessing.

How it works

01
Upload
PDF or text is parsed into numbered passages that keep their page numbers.
→
02
Ask Claude
The whole document, or its most relevant passages if it's very large, goes to Claude Opus 5.5.
→
03
Structured answer
Output must match a Pydantic schema: answer, confidence, and passage + quote citations.
→
04
Verify
Each quote is matched against the passage it cites and marked verified or flagged.

Key decisions

  • Structured outputs, not free text. Every response parses into a typed object; no fragile text parsing.
  • Server-side citation checks. Turns "trust the model" into a check that can be measured and audited.
  • Long context first, no vector database. Fewer missed answers, less infrastructure; a light ranker handles huge files.
  • Prompt caching. Follow-ups reuse the cached document, cutting cost 55% in testing.
  • Built for failure. Retries, clear errors for rate limits and timeouts, and a per-user limit protecting the API key.

Business value

  • Trust: reviewers check one quoted line, not a whole file.
  • Speed: minutes of searching become seconds.
  • Low cost: serverless, scales to zero when idle.

Engineering quality and next steps

  • 26 automated tests plus a reproducible live evaluation.
  • Public API with OpenAPI docs; deployed on Modal.
  • Next: OCR for scanned PDFs, multi-document Q&A, streaming.
